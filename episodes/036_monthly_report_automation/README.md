# Ежемесячный отчёт в Excel с Power Query — конспект №036

Настроим отчёт один раз. Затем добавим файл за новый месяц, нажмём «Обновить всё» и проверим результат.

**Что получится:** три запроса — «Детализация», «Отчёт_по_месяцам» и «Контроль». В отчёте будут месяц, количество позиций продаж и выручка после скидок.

**Что понадобится:** Excel для Windows с Power Query. Названия команд могут немного отличаться в вашей версии. VBA и DAX не используются. Формулы ниже написаны на языке M: аргументы разделяются запятыми даже в русской версии Excel.

## 1. Подготовьте файлы

Возьмите учебный набор [monthly](../../outputs/contoso_foods_v1_01a115b7/youtube/monthly/). Данные вымышленные, компания — «Контосо Фудс».

Скачайте папку и работайте с локальной копией. Если скачали ZIP, сначала распакуйте его. Нужны все 12 файлов из `input` и один файл из `acceptance`.

```text
monthly/
├── input/
│   ├── Sales_2025-01.xlsx
│   ├── Sales_2025-02.xlsx
│   ├── ...
│   └── Sales_2025-12.xlsx
├── acceptance/
│   └── Sales_2026-01.xlsx
└── Отчёт.xlsx             ← создайте эту книгу сами
```

Подключайте именно `input`, а не родительскую папку `monthly`: иначе январь 2026 может попасть в исходную загрузку раньше времени. Книгу отчёта храните вне `input`. Не создавайте внутри `input` подпапки с архивными копиями выгрузок.

В каждой исходной книге есть таблица `Sales` на листе «Продажи». Одна строка — позиция продажи, а не целый заказ. В каждой книге по 1 000 строк.

## 2. Объедините файлы в «Детализацию»

В видео этот запрос уже подготовлен. Чтобы повторить с нуля:

1. Создайте книгу «Отчёт.xlsx».
2. Выберите **Данные → Получить данные → Из файла → Из папки**.
3. Укажите свою папку `input`, нажмите **Преобразовать данные**.
4. Оставьте расширение `.xlsx` и имена, начинающиеся с `Sales_`. Исключите временные файлы `~$` и скрытые файлы. Для скрытых файлов можно раскрыть `Attributes`, выбрать `Hidden` и исключить значение `true`.
5. Не ограничивайте имена файлов строкой `2025`: иначе следующий год не загрузится.
6. Нажмите значок объединения в заголовке **Content**. В книге-образце выберите таблицу **Sales**, не весь лист.
7. Не включайте пропуск файлов с ошибками: отсутствующую выгрузку легко не заметить.
8. Назовите итоговый запрос **Детализация**. Вспомогательные запросы, созданные при объединении, оставьте.
9. Сохраните столбец имени файла — обычно **Source.Name**. Переименуйте его в **Файл**.

Объединение однотипных файлов и обработка через книгу-образец описаны в [документации Microsoft](https://learn.microsoft.com/en-us/power-query/combine-files-overview).

Проверьте типы данных. Если автоматический шаг уже превратил коды в числа, исправьте этот шаг или удалите его и назначьте типы заново от шага до преобразования. Простое преобразование числа обратно в текст не вернёт начальные нули.

| Поле | Тип | Назначение |
| --- | --- | --- |
| Файл | Текст | Имя исходной выгрузки |
| SaleLineID | Текст | Идентификатор позиции продажи |
| ProductID, CustomerID, WarehouseID, EmployeeID | Текст | Коды справочников |
| SaleDate | Дата | Дата продажи |
| Quantity | Целое число | Количество упаковок |
| UnitPriceRUB | Фиксированное десятичное число | Цена упаковки, рубли без НДС |
| DiscountPct | Десятичное число | Скидка: 7 означает 7% |
| Currency | Текст | Валюта; в этом примере RUB |

## 3. Рассчитайте выручку каждой позиции

Выберите **Добавление столбца → Пользовательский столбец**. Имя — **Выручка**. Вставьте выражение без начального знака `=`:

```powerquery
Number.Round(
    [Quantity] * [UnitPriceRUB] *
        (1 - (if [DiscountPct] = null then 0 else [DiscountPct]) / 100),
    2,
    RoundingMode.AwayFromZero
)
```

Формула: количество × цена × (1 − скидка / 100). Для этого учебного набора пустая скидка означает отсутствие скидки. Для других данных это правило нужно уточнять.

Например: 10 упаковок × 100 ₽ × (1 − 7 / 100) = 930 ₽.

Округляем каждую позицию до двух знаков, затем складываем позиции. Это может отличаться от округления только общей суммы. `RoundingMode.AwayFromZero` задаёт округление от нуля в случае ровно половины между соседними вариантами округления.

Задайте столбцу «Выручка» тип **Фиксированное десятичное число**. Загрузите «Детализацию» как таблицу на отдельный лист: **Главная → Закрыть и загрузить в… → Таблица → Новый лист**.

## 4. Создайте помесячный отчёт

Откройте редактор через **Данные → Запросы и подключения → Детализация → Изменить**.

1. Нажмите правой кнопкой по запросу «Детализация» → **Ссылка**.
2. Назовите запрос **Отчёт_по_месяцам**.
3. Добавьте пользовательский столбец **Месяц** с выражением:

```powerquery
Date.StartOfMonth([SaleDate])
```

4. Задайте тип **Дата**. Пятое и двадцать первое декабря 2025 превратятся в `01.12.2025`, но январь 2026 останется другим периодом. Функция возвращает начало месяца исходной даты: [Date.StartOfMonth](https://learn.microsoft.com/en-us/powerquery-m/date-startofmonth).
5. Выберите **Главная → Группировать по → Дополнительно / Расширенный режим**.
6. Поле группировки — **Месяц**. Добавьте две операции:

| Новый столбец | Операция | Исходный столбец |
| --- | --- | --- |
| Строк продаж | Количество строк | Не требуется |
| Выручка, ₽ | Сумма | Выручка |

7. После группировки отсортируйте «Месяц» по возрастанию. Группировка сама по себе не гарантирует порядок строк: [Table.Group](https://learn.microsoft.com/en-us/powerquery-m/table-group).
8. Загрузите результат как таблицу на новый лист.
9. В Excel задайте месяцу формат с месяцем и годом: например, `мммм гггг` в русской версии или `mmmm yyyy` в английской. Значение должно остаться датой, меняется только отображение. Выручку отображайте с двумя десятичными знаками.

### Полный код запроса «Отчёт_по_месяцам»

Это альтернатива действиям 3–7, а не дополнительный шаг. После создания ссылки откройте **Главная → Расширенный редактор** и замените код этого запроса целиком. Запрос «Детализация» уже должен существовать и содержать «Выручку».

```powerquery
let
    Источник = Детализация,
    ДобавленМесяц = Table.AddColumn(
        Источник,
        "Месяц",
        each Date.StartOfMonth([SaleDate]),
        type date
    ),
    Сгруппировано = Table.Group(
        ДобавленМесяц,
        {"Месяц"},
        {
            {"Строк продаж", each Table.RowCount(_), Int64.Type},
            {"Выручка, ₽", each List.Sum([Выручка]), Currency.Type}
        }
    ),
    Отсортировано = Table.Sort(Сгруппировано, {{"Месяц", Order.Ascending}})
in
    Отсортировано
```

До добавления января 2026 получится 12 периодов, в каждом по 1 000 позиций продаж.

## 5. Создайте запрос «Контроль»

В редакторе выберите **Главная → Новый источник → Другие источники → Пустой запрос**. Назовите его **Контроль**. Откройте **Расширенный редактор** и замените код целиком:

```powerquery
let
    T = Детализация,
    Итог = #table(
        type table [
            Файлов = Int64.Type,
            Строк = Int64.Type,
            РазныхID = Int64.Type,
            Выручка = Currency.Type
        ],
        {{
            List.Count(List.Distinct(T[Файл])),
            Table.RowCount(T),
            List.Count(List.Distinct(T[SaleLineID])),
            List.Sum(T[Выручка])
        }}
    )
in
    Итог
```

Загрузите таблицу на отдельный лист. Здесь:

- **Файлов** — количество разных имён файлов среди загруженных строк;
- **Строк** — число позиций продаж;
- **РазныхID** — число уникальных SaleLineID, дополнительная проверка повторов;
- **Выручка** — сумма округлённых сумм позиций.

В нашем наборе SaleLineID заполнены и уникальны для каждой позиции. Если число строк больше числа разных ID, проверьте повторы. Для собственных данных сначала уточните правила уникальности ключа.

Количество файлов не обнаружит пустой или пропущенный файл: оно считается по уже загруженным строкам. В примере используется плоская папка с непустыми книгами. Это контроль для данного примера, а не универсальная система проверки источников.

## 6. Добавьте новый месяц

1. Убедитесь, что до обновления в отчёте только январь–декабрь 2025.
2. Скопируйте `Sales_2026-01.xlsx` из `acceptance` в `input` один раз.
3. В Excel нажмите **Данные → Обновить всё**.
4. Дождитесь завершения обновления всех запросов.
5. Проверьте отчёт: январь 2026 должен быть отдельной строкой, а январь 2025 — остаться в начале списка.
6. Сверьте таблицу «Контроль» со значениями ниже.

| Состояние | Файлов | Периодов | Строк продаж | Разных ID | Выручка, ₽ |
| --- | ---: | ---: | ---: | ---: | ---: |
| Только 2025 год | 12 | 12 | 12 000 | 12 000 | 224 050 264,89 |
| Только новый файл, январь 2026 | 1 | 1 | 1 000 | 1 000 | 19 467 229,11 |
| После добавления нового файла | 13 | 13 | 13 000 | 13 000 | 243 517 494,00 |
| Повторное обновление без изменений | 13 | 13 | 13 000 | 13 000 | 243 517 494,00 |

Строка «Только новый файл» — ориентир для отдельной проверки января, не ожидаемый результат всего отчёта. Число периодов видно по строкам помесячного отчёта, отдельного поля в запросе «Контроль» для него нет.

Проверка прироста:

```text
13 000 − 12 000 = 1 000 новых позиций
243 517 494,00 − 224 050 264,89 = 19 467 229,11 ₽
```

Для сравнения с предыдущим месяцем:

```text
Декабрь 2025: 18 939 155,85 ₽
Январь 2026:  19 467 229,11 ₽
Изменение:      +528 073,26 ₽
```

В этом примере прошлые месяцы не меняются. Для выгрузок с исправлениями прошлых периодов понадобится отдельное правило обработки корректировок.

## 7. Почему нельзя группировать только по названию месяца

Такое выражение возвращает слово «январь», но не год:

```powerquery
Date.MonthName([SaleDate], "ru-RU")
```

Если сгруппировать по нему данные за два года, январь 2025 и январь 2026 объединятся:

```text
18 862 557,67 + 19 467 229,11 = 38 329 786,78 ₽
1 000 + 1 000 = 2 000 позиций
```

Общий итог останется правильным, а результат за месяц — нет. Поэтому проверяем не только итоговую сумму, но и период. Правильный вариант для этого отчёта — `Date.StartOfMonth([SaleDate])`: в значении сохраняется и год.

Если хотите воспроизвести ошибку, создайте отдельную ссылку на «Детализацию» после добавления января 2026 и сгруппируйте её по названию месяца. Основной отчёт не меняйте.

## 8. Повторите обновление и проверьте источники

Нажмите «Обновить всё» ещё раз без добавления файлов. Результат должен остаться тем же. В этой настройке запрос перечитывает входную папку, а не дописывает её строки к прошлому результату на листе.

Но если положить во входную папку копию выгрузки под другим подходящим именем, например `Sales_2026-01_copy.xlsx`, она тоже пройдёт фильтр и загрузится. Повторное обновление и повторный файл — разные ситуации.

Если сумма не совпала:

1. Проверьте, что подключена `input`, а не `monthly`.
2. Проверьте имена файлов и отсутствие копий.
3. Проверьте, что фильтр не ограничен 2025 годом.
4. Проверьте, что скидка делится на 100 и выручка округляется на каждой позиции.
5. Отфильтруйте «Детализацию» по столбцу «Файл» и проверьте даты SaleDate. Имя файла само по себе не доказывает, что внутри нужный период.
6. Если фильтровали сам запрос для диагностики, уберите этот временный шаг перед итоговым обновлением.
