# Ссылка или дубликат в Power Query — конспект №037

На одном изменении проверим разницу между командами **Ссылка (Reference)** и **Дублировать (Duplicate)**. Затем соберём помесячный отчёт из ссылки, не меняя исходную детализацию.

Среда: Excel для Windows с Power Query. Названия меню могут немного отличаться в вашей версии. VBA и DAX не нужны. Код ниже — язык M; разделители аргументов — запятые, в том числе в русском Excel.

## 1. Подготовьте рабочую копию

Если вы повторяли выпуск №036, сохраните копию книги с готовым запросом **Детализация**. Не экспериментируйте в рабочем отчёте, который отправляете коллегам.

Если начинаете с нуля, подготовка источника описана ниже. Используем [учебный набор monthly](https://github.com/renatlotfullin/powerbi-datasets/tree/main/episodes/036_monthly_report_automation/monthly):

- 12 книг `Sales_2025-01.xlsx` … `Sales_2025-12.xlsx` из папки `input`;
- одну книгу `Sales_2026-01.xlsx` из папки `acceptance`.

Скачайте и распакуйте файлы. В **рабочую копию input** добавьте январь 2026 ровно один раз. Для этого урока с самого начала нужны **13 файлов**. Книгу отчёта храните вне input. Не подключайте родительскую папку monthly: она содержит acceptance и может дать повторную загрузку января.

### Подготовка «Детализации», если её ещё нет

1. В Excel: **Данные → Получить данные → Из файла → Из папки**. Выберите рабочую input и нажмите **Преобразовать данные**.
2. Оставьте `.xlsx` с именами, начинающимися с `Sales_`. Исключите временные и скрытые файлы. Не ограничивайте имя 2025 годом. Не храните архивы и копии в этой входной папке.
3. Нажмите значок объединения в заголовке **Content**. В книге-образце выберите таблицу **Sales**. Не включайте пропуск файлов с ошибками.
4. Назовите основной итоговый запрос **Детализация**. Вспомогательные запросы объединения оставьте.
5. Сохраните имя файла, обычно **Source.Name**, и переименуйте столбец в **Файл**.
6. Задайте типы: SaleLineID и коды справочников — текст, SaleDate — дата, Quantity — целое, UnitPriceRUB — фиксированное десятичное число, DiscountPct — десятичное число. Если автоматический шаг уже потерял нули в кодах, исправьте его, а не преобразовывайте повреждённые числа обратно в текст.
7. Через **Добавление столбца → Пользовательский столбец** создайте **Выручка**. Вставьте без начального `=`:

```powerquery
Number.Round(
    [Quantity] * [UnitPriceRUB] *
        (1 - (if [DiscountPct] = null then 0 else [DiscountPct]) / 100),
    2,
    RoundingMode.AwayFromZero
)
```

8. Задайте «Выручке» тип **Фиксированное десятичное число**. Скидка 7 в этом наборе означает 7%, пустая скидка — 0. Суммы в рублях без НДС; округляем каждую позицию до копеек, затем складываем.
9. **Закрыть и загрузить в… → Таблица → Новый лист**. Сохраните книгу.

Подробная подготовка с дополнительными пояснениями — в [конспекте №036](https://github.com/renatlotfullin/powerbi-datasets/blob/main/episodes/036_monthly_report_automation/README.md).

Исходный результат для №037: **13 000 позиций, 243 517 494,00 ₽**, период — 2025 год и январь 2026. Одна строка — позиция продажи, не обязательно целый заказ. Полные числа проверим запросом контроля, а не ограниченным предпросмотром.

## 2. Создайте дубликат

1. Откройте «Детализацию»: **Данные → Запросы и подключения → правой кнопкой по запросу → Изменить**.
2. В списке запросов редактора нажмите правой кнопкой по **Детализация → Дублировать**.
3. Назовите новый запрос **Продажи_Копия**.
4. Сравните применённые шаги: скопирована текущая цепочка обработки.

Важно: копируем именно «Детализацию», до добавления тестового фильтра. Не дублируйте уже существующую ссылку: её код может сохранить обращение к базе, и получится другой эксперимент.

## 3. Создайте ссылку

1. Снова выберите **Детализация**, не созданную копию.
2. Правой кнопкой → **Ссылка**.
3. Назовите запрос **Продажи_Ссылка**.
4. Включите **Вид → Строка формул**, если она скрыта.

Начальный шаг обращается к базовому запросу. При имени базы «Детализация» выражение в строке формул:

```powerquery
= Детализация
```

В расширенном редакторе тот же смысл может выглядеть так:

```powerquery
let
    Источник = Детализация
in
    Источник
```

**Источник** здесь — имя локального шага, **Детализация** — имя другого запроса. Это разные вещи. Если в вашей книге сама база называется «Источник», ссылка будет обращаться к ней по этому имени. В этом конспекте используем имя базы «Детализация».

Ссылка начинает с результата базы, дубликат получает копию её текущих шагов. Это поведение описано в [документации Microsoft о запросах](https://learn.microsoft.com/en-us/power-query/queries-pane).

## 4. Создайте проверки количества и выручки

Счётчик предпросмотра может показывать не все строки. Для точного сравнения создадим две маленькие таблицы.

В редакторе: **Главная → Новый источник → Другие источники → Пустой запрос**. Назовите его **Контроль_Ссылки**. Откройте **Расширенный редактор** и замените код целиком:

```powerquery
let
    T = Продажи_Ссылка,
    Итог = #table(
        type table [Строк = Int64.Type, Выручка = Currency.Type],
        {{Table.RowCount(T), List.Sum(T[Выручка])}}
    )
in
    Итог
```

Создайте второй пустой запрос **Контроль_Копии**:

```powerquery
let
    T = Продажи_Копия,
    Итог = #table(
        type table [Строк = Int64.Type, Выручка = Currency.Type],
        {{Table.RowCount(T), List.Sum(T[Выручка])}}
    )
in
    Итог
```

Загрузите оба контроля как таблицы на отдельные листы через **Закрыть и загрузить в…**. Если запрос уже создан, в панели Excel «Запросы и подключения» откройте его контекстное меню → **Загрузить в…**. Выручку отображайте с двумя знаками после запятой.

Нажмите **Данные → Обновить всё** и дождитесь завершения всех запросов. До эксперимента обе проверки должны показать 13 000 строк и 243 517 494,00 ₽.

## 5. Измените только базу

1. Откройте редактор, выберите **Детализация** и её последний шаг.
2. В SaleDate откройте фильтр → **Фильтры дат → До…**.
3. Укажите **01.01.2026**. Условие должно быть строго «раньше», не «раньше или равно».
4. Назовите добавленный шаг **Тест_До2026**.
5. Не изменяйте исходные Excel-файлы, «Продажи_Копия», «Продажи_Ссылка» или функцию обработки файла-образца.
6. Закройте редактор с применением изменений. Выполните **Обновить всё**, дождитесь завершения и проверьте оба контроля.

Эквивалент фильтра в M, для понимания:

```powerquery
Table.SelectRows(#"Предыдущий шаг", each [SaleDate] < #date(2026, 1, 1))
```

«Предыдущий шаг» — условное имя, не готовый запрос. При вставке в строку формул добавьте начальное `=` и подставьте точное имя вашего последнего шага. Проще создать фильтр через интерфейс.

| Результат после фильтра базы | Позиции | Выручка, ₽ |
| --- | ---: | ---: |
| Детализация | 12 000 | 224 050 264,89 |
| Продажи_Ссылка | 12 000 | 224 050 264,89 |
| Продажи_Копия | 13 000 | 243 517 494,00 |

Разница — январь 2026: **1 000 позиций и 19 467 229,11 ₽**. Копия обновилась, но новый шаг базы не стал частью её собственной цепочки.

## 6. Верните исходное условие

В **Детализации** удалите только временный шаг **Тест_До2026**. Не удаляйте запрос или исходные строки.

Снова примените изменения и обновите книгу. Оба контроля должны вернуться к **13 000 строкам и 243 517 494,00 ₽**. Перед следующим этапом убедитесь, что январь 2026 вернулся.

## 7. Сделайте помесячный отчёт из ссылки

Теперь меняем только **Продажи_Ссылка**:

1. **Добавление столбца → Пользовательский столбец**. Имя — **Месяц**, выражение:

```powerquery
Date.StartOfMonth([SaleDate])
```

2. Задайте тип **Дата**.
3. **Главная → Группировать по → Дополнительно / Расширенный режим**.
4. Группируйте по **Месяц**. Добавьте операции:

| Новый столбец | Операция | Поле |
| --- | --- | --- |
| Строк продаж | Количество строк | Не требуется |
| Выручка | Сумма | Выручка |

5. Отсортируйте Месяц по возрастанию.
6. Переименуйте запрос в **Отчёт_Ссылка** и загрузите таблицу на новый лист.

### Альтернатива: полный код помесячной ветки

Вместо действий 1–5 можно заменить код **Продажи_Ссылка** в расширенном редакторе на следующий. Не вставляйте его в базовую «Детализацию» и не создавайте второй запрос с тем же именем.

```powerquery
let
    Источник = Детализация,
    ДобавленМесяц = Table.AddColumn(
        Источник, "Месяц",
        each Date.StartOfMonth([SaleDate]), type date
    ),
    Группировка = Table.Group(
        ДобавленМесяц,
        {"Месяц"},
        {
            {"Строк продаж", each Table.RowCount(_), Int64.Type},
            {"Выручка", each List.Sum([Выручка]), Currency.Type}
        }
    ),
    Сортировка = Table.Sort(Группировка, {{"Месяц", Order.Ascending}})
in
    Сортировка
```

Результат — **13 строк-периодов**. В каждом месяце по 1 000 позиций, суммарно 13 000. Для января 2026 выручка равна **19 467 229,11 ₽**, общий итог — **243 517 494,00 ₽**. Дату можно отобразить в Excel как месяц и год, сохранив её тип даты.

В «Детализации» остаются 13 000 исходных позиций: группировка дочернего запроса не меняет базу.

### Что теперь покажет Контроль_Ссылки

После переименования проверьте его первую строку: `T = Отчёт_Ссылка`. Если ссылка на старое имя не обновилась, исправьте её вручную.

Его поле **Строк** теперь равно **13**, потому что считается число строк помесячного отчёта. Это не потеря продаж. Чтобы проверить количество позиций после группировки, складывайте поле **Строк продаж**. Контроль_Копии по-прежнему показывает 13 000 строк детализации.

## 8. Откуда создавать следующий отчёт

Если нужен отчёт по товарам, создавайте новую ссылку на **Детализацию**, а не на готовый **Отчёт_Ссылка**: после группировки по месяцам в нём уже нет ProductID и отдельных позиций.

Общие правила подготовки держите в базе. Фильтр, который нужен только одному получателю отчёта, добавляйте в соответствующую ветку.

## 9. Две важные оговорки

**Дубликат не замораживает данные.** Он сохраняет копию текущих шагов. Если его источник изменится, при обновлении результат тоже может измениться. Кроме того, дубликат может использовать те же вспомогательные функции и параметры, что и база. В нашем объединении папки изменение общей обработки файла-образца может повлиять на обе ветки.

**Ссылка не гарантирует ускорение.** Её преимущество — общая логика в одном месте. Отдельные ветки могут вычисляться отдельно; нельзя обещать единственное чтение файлов только потому, что используется Reference. Подробнее — [пояснение Microsoft о связанных запросах](https://learn.microsoft.com/en-us/power-bi/guidance/power-query-referenced-queries).

## Если результат отличается

- Обе ветки сразу дали 12 000 строк: проверьте, не создан ли дубликат уже после фильтра, есть ли январский файл и не дублировали ли вы ссылку вместо базы.
- Обе ветки не изменились: проверьте, куда добавлен фильтр, и завершилось ли обновление.
- Строк больше 13 000: проверьте копии файлов и подключение родительской папки вместо input.
- Ошибка имени запроса: сверяйте «Детализация», «Продажи_Ссылка» и «Продажи_Копия» с именами в вашей книге. Имя шага и имя запроса могут различаться.
- После группировки контроль показывает 13: теперь он считает месяцы. Сумма «Строк продаж» должна быть 13 000.

## Итоговая памятка

| Задача | Выбор |
| --- | --- |
| Использовать общую подготовку в нескольких результатах | Ссылка |
| Взять текущие шаги и дальше менять их отдельно | Дублировать |
| Сохранить неизменный исторический результат | Ни одна команда сама по себе не создаёт архив данных |

После практики проверьте, что временный фильтр базы удалён, январь 2026 вернулся и результаты сохранены в учебной копии книги.
